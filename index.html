marstack-cloud

Cloud platform for bare metalGitHub ↗
  • Go
  • QEMU
  • Cloud Hypervisor
  • Firecracker
  • Linux
  • Treats container, VM, microVM and sandbox as one resource type rather than four separate products.
  • Native routing with no encapsulation in the data path — each node owns a slice of the address space.
  • A node agent that pulls its desired state instead of being pushed to, so a node can rejoin without orchestration.
  • Objects modelled on the shapes cloud users already know, so the mental model transfers.
2026

marstack-container

OCI runtime written from scratchGitHub ↗
  • Rust
  • OCI
  • seccomp
  • cgroups
  • Linux
  • A container runtime built from nothing, not a fork, so every syscall it makes is a deliberate choice.
  • Measured privileged kernel surface: 1,570 kernel functions reached against runc’s 2,603 and crun’s 2,118.
  • Explains container failures from kernel state rather than handing back an exit code.
  • Drops in as a Docker runtime, so the comparison can be run on a real workload.
2026

marstack-secrets

Secret store that boots sealedGitHub ↗
  • Go
  • Shamir
  • Envelope encryption
  • PostgreSQL
  • Boots sealed: without an unseal quorum it serves nothing, by design.
  • Envelope encryption bound to tenant, path and version, so a leaked ciphertext is useless elsewhere.
  • Shamir secret sharing for unsealing, default-deny policy, and leases on every issued secret.
  • Refuses to start without a writable audit log — an unauditable secret store is worse than none.
2026

marstack-access

Identity-aware access for LinuxGitHub ↗
  • Go
  • SSH CA
  • Certificates
  • Linux
  • No standing credentials: access is a short-lived certificate issued per session.
  • Agentless, built on an SSH certificate authority, so target hosts need nothing installed.
  • Certificates never reach the user’s machine, which removes the thing worth stealing.
  • Tamper-evident audit with sessions recorded as text you can grep, not video you cannot search.

marstack-govern

Multi-tenancy and governance for KubernetesGitHub ↗
  • Go
  • Kubernetes
  • Connect RPC
  • PostgreSQL
  • Runs the request loop where divisions ask for a namespace, quota, access or a preview environment, and a platform team decides.
  • One rule throughout: every fact it shows is derived from the platform, never typed in by a human.
  • Nobody declares what is running, who owns it, or what it costs — it is read from the cluster.
  • Ships as a single binary, margov.

marspay

Indonesian e-walletGitHub ↗
  • Go
  • PostgreSQL
  • Ledger
  • Risk engine
  • Instant merchant payout at T+0 rather than the usual next-day settlement.
  • Real-time risk holdback that withholds part of a payout while a transaction still looks risky.
  • Payment rails are simulated on purpose — operating the real ones in Indonesia requires a PJP licence.
  • Double-entry ledger underneath, because a wallet that cannot reconcile is not a wallet.

xdp-lb

L4 load balancer on the XDP hookGitHub ↗
  • Rust
  • C
  • eBPF
  • XDP
  • Maglev
  • Load balancing that runs on the XDP hook, before the kernel network stack allocates an sk_buff.
  • C data path for the per-packet work, Rust control plane for everything that can afford to allocate.
  • Maglev consistent hashing so backends can come and go without reshuffling every existing flow.
  • Documented honestly: the default runs in SKB mode on veth, and those numbers are not native XDP numbers.
