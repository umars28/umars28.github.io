Kill a backend and read last rebuild changed. Maglev only reassigns the slots that belonged to the dead backend, so established flows on the survivors keep landing where they were. Switch to naive modulo hashing and do it again — nearly every slot moves, and every flow without a conntrack entry lands on a different server mid-connection.

WHY THE DATAPATH NEVER DECIDES

Health checking, weight calculation from Prometheus, ARP resolution, drain state — all of it runs in the control plane and lands in a BPF map. The datapath reads maps and nothing else.

The consequence is the whole point: however elaborate the control-plane logic gets, the per-packet cost stays flat. Weights that track backend CPU in real time still resolve to a single array lookup.

Weights are virtual nodes. A backend with weight 3 gets three entries in the maglev permutation, so it claims roughly three times the slots — without the datapath knowing what a weight is.
